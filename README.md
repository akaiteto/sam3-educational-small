# mini SAM 3（仕組みを学ぶための小さなSAM 3）

SAM 3 の画像用の検出器（公式 [facebookresearch/sam3](https://github.com/facebookresearch/sam3) の `Sam3Image`）を、論文（arXiv:2511.16719、特に付録C）の記述に合わせて、CPUで20分ほどで学習できる大きさに書き直したものです。実用性はありません。本物の重みも使いません。

## 動かし方（Windows PowerShell の例）

```
git clone https://github.com/akaiteto/mini-sam3.git
cd mini-sam3
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install torch --index-url https://download.pytorch.org/whl/cpu
.\.venv\Scripts\python.exe -m pip install numpy scipy matplotlib

.\.venv\Scripts\python.exe demo.py --ckpt none     # 学習前：ランダムな重みで、各工程のテンソルの形を確認する
.\.venv\Scripts\python.exe -u train.py             # 3段階で学習する（2コアのCPUで20〜25分。--scale 0.5 で約半分）
.\.venv\Scripts\python.exe demo_pretrain.py        # 段階1の結果：画像と言葉が結びついたか
.\.venv\Scripts\python.exe demo.py                 # 最終結果：言葉で指定した物体のマスクと枠
.\.venv\Scripts\python.exe demo.py --ckpt mini_sam3_stage2.pt --no_presence   # プレゼンストークンを学習する前と比べる
```

Mac・Linux では `.\.venv\Scripts\python.exe` を `.venv/bin/python` に読み替えてください。

- データは学習中にその場で作るので、ディスクには溜まりません。
- 保存されるのはチェックポイント3つ（各約4MB）と、図のPNGだけです。
- コードは Claude Code で作成しました。

## 課題（合成データ）

`data.py` は、64x64画素の画像に色つきの図形（red/green/blue × circle/square/triangle）を1〜3個描きます。プロンプトは「red circle」「circle」「blue」のような短い名詞句です。モデルは、プロンプトに当てはまる物体を**全部**見つけ、物体ごとにマスクと枠を出します。当てはまる物体が1つもない画像もあり、そのときはプレゼンストークンが「存在しない」と答えるべきです。

## 学習の段階（train.py）

| 段階 | 論文 | このコード |
|---|---|---|
| 1 | パーセプション・エンコーダを、画像と文の組54億件で対照学習 | 画像エンコーダとテキストエンコーダを、合成画像と15個のコンセプトで対照学習（SigLIP型）。800ステップ |
| 2 | 検出器の事前学習 | 検出器の学習。プレゼンスなし。エンコーダの学習率は1/10。3000ステップ |
| 3 | プレゼンスの損失を加え、学習率を下げた約5千回の追加学習 | プレゼンスの損失を加える。プレゼンスヘッド以外の学習率は1/10。600ステップ |
| 4 | 追跡器の学習 | なし |

段階2と段階3では、コンセプトが存在しない画像の扱いが変わります。
- 段階2：存在しない画像では、全クエリを「一致しない」として学習します。
- 段階3：論文と同じく、存在しない画像ではクエリを学習しません。プレゼンストークンだけが学習します。

## 処理の流れと、論文・公式コードとの対応

| 工程 | このコード（model.py） | 公式（sam3/model/、*は推定） | このコード | 論文 |
|---|---|---|---|---|
| 1 画像エンコーダ | `ImageEncoder` | `vitdet.py`* | 64画素、8x8マス、4層、全体アテンションは2・4層目 | 1008画素、72x72マス、32層、全体アテンションは4層だけ |
| 2 テキストエンコーダ | `TextEncoder` | `text_encoder_ve.py` | 4トークン、2層 | 32トークン、24層 |
| 3 見本エンコーダ | `ExemplarEncoder` | `geometry_encoders.py`* | 枠＋枠内の特徴＋位置＋正負ラベル → 小さなTransformer（1層） | 同じ構成（ROIプーリング） |
| 4 融合エンコーダ | `FusionEncoder` | `encoder.py` | 3層：セルフ → プロンプトへのクロス → MLP | 6層、同じ順 |
| 5 デコーダ | `Decoder` | `decoder.py` | クエリ10個、3層、boxRPB、枠の反復修正、look-forward-twice | クエリ200個、6層、同じ仕組み |
| ├ プレゼンストークン | `presence_token` ＋ `presence_head` | 同名 | | |
| ├ 補助クエリ | `num_hybrid=20`、正解1つに3クエリ | | 学習時だけ | ハイブリッドマッチング |
| 6 マスクヘッド | `MaskHead` | `maskformer_segmentation.py`* | 内積でマスク ＋ 意味的ヘッド | MaskFormer方式 ＋ 意味的ヘッド |

## 各工程で、何が何をするか

1. **画像エンコーダ**は、画像を8x8画素ずつのマス目（64個）に切り、各マス目を64次元のトークンにします。位置埋め込みを足したあと、セルフアテンションとMLPを4層通します。1・3層目では、各マス目が同じ窓の16マスとだけ内積を取ります。2・4層目では、全64マスと内積を取ります。最後にネックが、32x32の細かい特徴マップと、8x8の検出器用の特徴マップを作ります。
2. **テキストエンコーダ**は、「red circle」を単語IDの列にし、因果マスク付きのセルフアテンションを通して、テキストトークンを出します。
3. **見本エンコーダ**は、見本として与えた枠を1つのトークンにし、小さなTransformerで画像特徴をクロスアテンションさせます。テキストトークンと見本トークンを連結したものが、プロンプトトークンです。
4. **融合エンコーダ**は、まずテキストトークンの平均を全画像トークンに加算します。次に、画像トークン同士のセルフアテンション、画像トークン（Q）がプロンプトトークン（K・V）を見るクロスアテンション、MLPを繰り返します。
5. **デコーダ**は、プレゼンストークン1個とオブジェクトクエリ10個を連結し、層ごとに次の4つを繰り返します。各層で、各クエリは自分の枠の修正量を出します。
   - クエリ同士のセルフアテンション
   - プロンプトへのクロスアテンション
   - 画像トークンへのクロスアテンション（boxRPBで、自分の枠の周りを強く見る）
   - MLP
6. **スコア**：各クエリの出力とプロンプトの平均の内積が、「このクエリが一致する確率（存在する前提）」になります。プレゼンストークンの出力が、「画像内に存在する確率」になります。最終スコアは2つの積です。
7. **マスクヘッド**は、ピクセル埋め込みを作り、各クエリのマスク埋め込みとの内積でマスクを出します。意味的ヘッドは、各画素が「プロンプトに当てはまる物体のどれか」に含まれるかを出します。

## 比べて学ぶためのフラグ（train.py）

| フラグ | 外すもの | 見どころ |
|---|---|---|
| `--no_box_rpb` | boxRPB | 枠の損失（l1・giou）の下がり方 |
| `--no_hybrid` | 補助クエリ（1対多） | 学習初期の cls・l1 の下がり方 |
| `--no_aux` | 各層の補助損失 | 最終層以外の枠の質 |
| `--no_lft` | look-forward-twice | 枠の損失 |
| `--skip_stage1` | 事前学習 | 段階2の初めの下がり方、未知の組み合わせへの強さ |

## 省略したもの

- 動画の追跡器（SAM 2由来のメモリ）
- クリック操作（PVS）用の幾何クエリ
- DAC-DETR、Align損失
- 曖昧さ対策のモジュール（2つのエキスパート）
- 本物の規模の事前学習

## 確認ポイント

- `demo_pretrain.png`：枠を一度も使っていない段階1で、白枠（正解）のところが明るくなっているか。
- `demo_result.png`：
  - 1行目：プロンプトごとのマスクと枠
  - 2行目：意味的ヘッドの出力（物体を区別せず、当てはまる場所全体が光る）
  - 3行目：クエリごとのスコア
- `demo_attention.png`：融合エンコーダの層ごとに、画像の各マス目が「red」「circle」などのトークンをどれだけ見たか。
- `--ckpt mini_sam3_stage2.pt --no_presence` と最終結果を比べると、プレゼンストークンが誤検出を抑えているかが分かります。
